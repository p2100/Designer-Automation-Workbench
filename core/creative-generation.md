# 新站视觉创作：从首页效果稿到真实页面

这是 Coupon、App、Games 新站及明确授权重做的默认创作方法，配合 `core/generation-default.md` 与对应站型规则使用。目标是先把适合本站的视觉方向做出来、看清楚，再实现完整站点；已有站局部维护或用户明确要求还原指定设计时，遵守该任务的参考和修改范围，不擅自重做或生成无关方案。

## 1. 先弄清这个站要让谁做什么

Agent 根据真实需求与资料确定站型、用户、主要动作、品牌调性、市场语言、真实数据和页面用途，再决定视觉语言。按 `core/creative-learning.md` 检查本机及团队是否有适用于本任务、同站型同页面的设计师创作观察，并结合本次明确要求判断；没有记录就使用默认流程。不能先随机选漂亮配色，然后硬套数据。把以下决定简洁写进任务记录，由 Agent 自行完成，不要求设计师填写：

- 首页最先看到什么：Coupon 的真实优惠/商家与购物入口；App 的真实应用与发现入口；Games 的真实游戏与进入路径。实体、分类和主要操作以本次数据及专项规则为准。
- 该站的品牌关键词、视觉气质、主次色与强调色、字体角色、图像/插画方式、卡片与按钮语言、页面密度、背景和留白节奏。每项说明为何适合此站，而不是拼一串风格形容词。
- 必须出现和明确不能出现的模块、真实内容、首要动作、参考、允许发挥的范围。记录用户明确选择的参考；参考用于学习构图、信息组织、节奏及质感，不自动复制品牌、文案、按钮、颜色、假数字或广告空白。
- PC 首屏及以下的阅读顺序，以及手机如何重新组织导航、主视觉、卡片和动作。信息多的卡片给足空间，信息少的可更紧凑；四层间距和实际文本容量在页面里成立。

优先利用用户提供、已确认或现有规范中适用的参考；必要时由 Agent 实际查看同类型的优秀页面，记下可取之处与不应照搬的地方。参考不可用就记录缺口，不能声称已看过，也不把截图中的名称、优惠、评分、游戏运行能力等当真实数据。

## 2. 先用 Image 生成首页视觉方向稿

对新站及明确授权重做首页，默认先使用当前宿主实际可用的 **Codex Image / Image 生图能力**生成符合本站类型的首页效果稿，作为视觉设计参考，再进入页面代码。实际调用以当前宿主工具和权限为准；独立 Harness 不因安装了规则包就自动拥有 Codex Image。调用前检查工具可用性；不可用或生成失败时如实记录，继续可独立完成的资料与结构工作，不宣称方向稿已生成，也不拿无关图片冒充。

让生成工具理解这是一张**网页首页设计稿**，包含站点导航、首屏、首屏之后的主要内容和版面关系，而不只是生成一张 Banner。提示词使用本次已确认的信息，至少说明：

1. **类型和目的**：站点类型、访客要完成的事、英文或其他实际语言、首页的主要真实内容与动作。
2. **布局和内容**：顶部导航、主要视觉焦点、首屏与下方模块、卡片/列表角色、信息顺序，及该站型明确不能出现的模块。
3. **品牌与视觉**：选定调性、色彩角色、字体性格、图像媒介、背景/纹理、卡片形态、按钮、留白及整体节奏。要求内容可读、商业/产品目的清楚，风格与本站内容相符。
4. **实际约束**：分别描述 PC 与手机的组织；保留清晰文字、按钮与内容空间，不画无意义装饰、虚构排行榜/评分/优惠或错误的业务入口。图片中的虚构文案、Logo 和数据只是模型可能产生的示意，不能直接作为真实内容。

默认先做一套有完整构图的方向，实际观察后再针对问题修正；用户要求多方案、多品牌或首稿方向不成立时，生成真正不同的方向并比较，而不是机械地为每站强制生成固定数量。多站方案应在页面结构、图文组合、卡片组织或动作设计上有合理区别，仅换色、替换图片或换一套相同圆角不算差异。用户明确要求还原已有设计时，不为追求多样性破坏该参考。

保留生成的原图、提示词、实际工具/素材来源与对应站点、阶段和选用原因；后续修改另留新稿，不能覆盖已确认版本。方向稿是视觉参考：图上看起来像网站，不代表链接、数据、响应式或视觉验收已经完成。用户未要求先选稿时，Agent 按站型和质量自行评估推进；明确要求设计师选稿或确认方向时，把可比较的实际方案交给设计师。

### 按站型组织效果稿

- **Coupon**：让优惠购物成为焦点，突出真实商家与优惠入口、购物型主视觉、精选与普通卡片的层次；画面应有商业吸引力和本站自己的按钮/卡片语言。可选择摄影、插画、拼贴，或以真实商家/优惠为核心的原创构图；不强迫所有站都使用人物、购物袋或同一大图。图中优惠文字和商家标志不作为真实数据，实际页面由真实数据及官方素材呈现。
- **App**：让真实应用的发现和获取路径清楚，围绕应用图标、名称、分类、评分等真实且有来源的字段组织首页；推荐大卡、普通图标组和文章各有用途。图像主导的 Banner 要有独立的编辑主视觉与可辨认的应用身份；生成图不能伪装成真实应用截图或官方认证。标题区不加介绍性小字，不用 Games 三列/在线游玩规则设计下载站。
- **Games**：以游戏画面和可进入的游戏卡片为主体，形成有游戏气氛的配色、背景和动作；遵循全宽首页、无分类模块等当前专项要求。画出适合触控与 hover/focus 的信息呈现，但不强制每站都出现同一种悬浮按钮；不要把效果稿里的假游戏名称、运行画面或加载状态视为真实。

## 3. 对效果稿做设计判断，再拆成可实现方案

Agent 实际查看图稿，检查首要焦点、前两屏、卡片信息、背景与图像、字体、颜色、动作、空白和整页节奏；判断是否像该类型的网站，是否既有特色又易于使用。对照适用的已确认参考，检查是否过于普通、无意义装饰、图片喧宾夺主、购物/应用/游戏内容靠后、按钮千篇一律、标题挤压或手机无法重排。独立方向审核可用时由独立角色集中评价；不能把生图成功或模型自评当作独立审核或用户认可。

将选中的方向整理成实际设计决定：

- **页面骨架**：每个模块的作用、顺序、内容量、PC 与手机布局、入口和关联页面。
- **视觉语言**：背景/内容/强调色的角色、字体及层级、边框与形状、背景纹理、图文比例、四层间距；颜色必须服务内容与对比度，不规定所有站使用同一套 token。
- **组件家族**：普通卡、重点卡、列表、标题栏、按钮、导航、页脚及其真实状态；同用途保持一致，不同用途可有合理差异。栏目浏览控制按 `knowledge/pages/brand-section-actions.md` 处理，不把普通正文/页脚链接一律变成按钮。
- **手机适配**：单独决定内容顺序、列数、图文关系和操作归属；对照相同用途的真实手机页面，不能把桌面截图缩小当作手机设计。
- **资产清单**：区分效果稿、需要单独制作的 Banner/插画/背景/图标、真实 Logo、真实产品截图与原有图片。生成素材时围绕最终展示尺寸、裁切、主体和留白单独制作并保存来源；不能直接把一整张网页稿裁成不可编辑的网页。

如稿图中的字、Logo、商品、应用截图或数据不真实，以核验过的原始数据和真实资产为准。用户选定的视觉稿需要落成可使用页面，不凭想象添加它没有的无关模块；真实业务、可读性和交互底线不因照图而放宽。

## 4. 按页面职责继续设计，再建真实页面

首页方向确定后，Agent 针对每种实际页面分别梳理用户要完成的任务、必要模块、数据与状态、主次动作及 PC/手机布局，延续本站已选的字体、色彩角色、图片与组件语言，但不把首页构图直接套到每个内页。重要或复杂页面可使用 Image 制作该页方向稿并实际查看；图稿依据该页面和站型要求，不捏造事实、不替代真实实现。具体是否需要单独出稿按复杂度、用户要求和可用能力判断。

- **Coupon**：商家页以真实商家身份与有效优惠列表为主；单券详情围绕完整主券、正确领取操作与真实关联推荐。分类、文章和信息页各按实际用途组织，不把首页促销 Banner 复制到所有页面。
- **App**：detail 帮用户了解对应应用，version 承接真实获取渠道；分类与文章承担发现和内容职责。图标、真实截图、平台信息和动作都指向同一应用；不使用 Games 在线玩结构。
- **Games**：detail 清楚组织真实游戏身份、操作说明和推荐；在线游戏页围绕实际运行、loading 和底部信息，商店专属条目走真实商店流程。依最新规则做手机重组，并保留本站游戏氛围。

## 5. 建真实页面，边看边改

先实现首页及一条代表性真实主路径：Coupon 的优惠/商家详情；App 的 detail → version → 真实渠道；Games 的真实 detail 及可用游玩或商店分支。用可编辑 HTML/CSS 实现文字、卡片、导航和按钮，保持内容实体映射；脚本只用于真实交互和必要动态数据。效果图不能直接当整页背景替代实际页面。

把需要的生成素材单独接入项目，检查实际 PC/手机裁切、清晰度、加载与最终 ZIP；保留官方 Logo、应用/游戏真实截图和真实 runtime 的身份。Coupon 主视觉可按其规范使用原创商业构图或授权素材；Games loading 和授权新做的游戏操作图标遵循专项生图要求。不要把图稿中的虚构文字、生成图上的优惠数字或未经核验的 UI 冒充真实内容。

在浏览器实际看完整首页和主要内页，比较效果稿的主次关系与真实页面，检查图片、文字、卡片、按钮及手机组织是否真正成立；逐项调整源码而不是只改文档或继续叠加装饰。先让普通组件、真实长短内容和末行成立，再扩展全部页面。多 Games 站按其专项逐站完成；按需比较不同品牌的同用途 PC 和手机页面，避免套壳。

## 6. 完整审核、返工、交付和经验

遵循 `core/generation-default.md` 的自检、独立审核、集中修复、复查与交付。实查真实浏览器、交互和数据；自动检查、效果图或截图文件都不能单独证明视觉通过。方向稿被用户否决就记录为否决并调整，不能把旧内部结果当用户认可。创作过程中按 `core/creative-learning.md` 记录设计师真实表达的满意点和调整；设计师查看准确候选并明确确认后，再按 `core/experience.md` 保存符合条件的已验证经验。品牌偏好和具体图稿保留适用范围，不能自动升级为所有站的公共硬规则。
