# 两小时改稿执行预算

目标口径：已有初稿后，从设计师开始本轮调整到准确候选人工确认、中央站点库成功回执，共120分钟。模型、首次准备、构建、检查和上传等待均计入。经验后台补传不阻塞回传；queued、仅本地准备、仅人工认可都不是完成。

Agent 在收到本轮调整时使用已有工作区并启动一次计时。首次 adjustment open/start 在 checkout、识别、检索和规则冻结前保存命令接收起点；已有任务用 audit timer-start。重复命令、失败重试、结构错误和新候选不重置同任务计时。没有可靠起点时如实报告 not-started，不能推算达标。新建任务不得用于掩盖原任务超时。

| 时间 | 工作与可查看结果 |
| --- | --- |
| 0–15分钟 | 集中看稿；保留原话，按组件家族归组，确认页面/设备/状态与真实调用范围 |
| 15–50分钟 | 首轮成组修改，完成部分持续出预览；同时做受影响检查 |
| 50–65分钟 | 设计师集中看同一候选的PC和手机，收齐剩余反馈 |
| 65–85分钟 | 第二轮修正，保留逐项已改/待改/待确认状态 |
| 85–105分钟 | 收尾受影响回归，核对经验应用；设计师查看准确最终候选并确认 |
| 105–110分钟 | 直接回传，核对中央成功回执和版本 |
| 110–120分钟 | 重试及异常缓冲 |

两轮是预算，不是强制结案。第二轮仍有硬失败、明显视觉问题或未完成反馈就继续处理并记录超时，不降低质量标准或裁掉调用页。新增LP、模块或结构修复保留范围变化记录，时间仍计入本轮。

执行时按自然语言反馈准备 adjustmentItems，一次修同家族实际受影响实例。计划冻结适用有效经验，主观创作参考只选择少量高相关条目，其他参考按需查看。品牌构图、真实数据与业务要求保留。参数和局部样式直接修改现有源码，不重新生成整站；未知影响先定位，预览保持可用。

构建后立即展示候选，再执行局部复验。独立浏览器组默认最多2个并行，复制等共享剪贴板检查串行；相同访问合并、未变有效证据复用。经验激活与站点上传独立持久化、独立重试，设计师只确认准确版本一次。

audit status 的 timings 分别显示准备/构建/冻结、浏览器访问和全程时钟。全程只有当前候选仍有准确认可、对应站点库回执为 uploaded 才结束。超时上传仍记录为 completed 且 withinBudget=false；时限不自动批准任何候选。

上传回执的原生时钟与最终交付口径分别保留。Agent 还须核对实际中央版本入口与已确认稿一致；最终两小时报告采用该核对完成和上传回执中更晚的结束时间。若版本目录下样式、导航或运行资源损坏，或设计师对当前稿继续返工，首次回传耗时只是历史记录，不代表最终视觉认可或最终达标；如实重开，并保留可靠的实际起点，不能重置时钟掩盖未完成反馈。

以各站型真实任务分别验收两小时达标率、首稿同类缺陷数、设计师返工轮数及等待时间。技术回放耗时、组件浏览器基准和真实设计师改稿耗时分别报告，不互相替代。
