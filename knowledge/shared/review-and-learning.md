# 公共检查、复查与经验

## SHARED-EVIDENCE-001 · 可定位的真实证据

每项结论绑定站点、页面/路由、模块、候选身份、宽度、状态、观察和实际证据。看完整页、模块组、短长与末项；几何 JSON 不替代像素，截图生成不等于审核者已看过。所有路由/内部链接/媒体及逐实体身份目标核对，与代表视觉取样分开记录。没有能力或没有执行记 not-run；条件不成立才记有原因的 not-applicable。页面专项待补齐须保留缺口，不借公共规则宣称专项完整。

## SHARED-RECHECK-001 · 修复后检查与验收边界

先保存修前问题及正常样本，在独立源码副本修改并构建新候选，复查原问题与受影响回归。冻结后不改产物或输入；继续修复建立关联的新 run。源码完成、技术自检、视觉/交互复查、独立审核、发布和用户认可分别记录。作者可独立完成检查/修复/复查反馈；独立验收由另一个上下文或人员实际执行。哈希与封评程序只核验记录一致性。

## SHARED-LEARN-001 · 按设计师确认沉淀与共享

通过现有 designer_experience MCP 保存真实反馈草稿。只有准确候选复验、设计师实际查看并明确确认后，按 core/experience.md 自动提炼和共享来源站点内的结论；未知原因与一次性文案记录跳过理由。同一原则经至少两个独立来源站点确认后，再按既有服务规则推广，单站审美偏好保持本站范围。专项经验的页面键按站型隔离，正式公共方法在 knowledge/shared 维护。既有纠错、撤回、离线保留和自动补传照常执行；queued 不能说成已共享，不让设计师填 JSON、手动 sync 或找维护者发布。任务固定经验快照，后续共享不热改已开始任务。
