# Games 验收经验的适用与落地

来源：[用户提供的01–40经验规则](acceptance-experience-20261028.md)，2026-10-28。原文保留，本文说明在本包内如何使用。用户当次新要求优先；项目授权范围、真实数据与既有冻结快照不被此文自动变更。

- 01–04：先确认站点、参考、实体、预览及当前授权，建立同站一致、跨站不同的组件系统。
- 05–11：按PC、平板、手机和实际断点设计；共同检查网格容量、末行、主次区、文字和累计留白；隐藏模块后释放空间。
- 12–20：品牌、搜索和页脚按项目配置；卡片名称与真实评分按卡型展示；悬浮、键盘焦点和触屏保持可用，同类跨页一致，不同站保留差异。
- 21–28：真实文案、有效链接、适合目标尺寸的图片、清晰度与加载状态；背景预算须由项目明确，不能将某站20KB限制推广。
- 29–36：仅在网页游戏分支启用；按实体真实能力处理详情、运行、方向、加载、全屏和广告。商店分支不生成假试玩；广告和全屏不能因为本规则自动开启。
- 37–40：明确批准进行验收时，按实际候选记录路径、断点、功能和视觉证据；通过、未通过、未测试、不适用分别记载，理由和候选可追踪。用户要求不审核时不强行执行，但不称已通过。

## 参数与工具边界

先记录实际页面、站点类型、能力开关、断点、容器、卡型和来源；未知保持待确认。只有用户或项目合同授权时采用具体尺寸；平台截图中的数值和站点专属配色不得自动推广。若项目未提供参数，遵循当前本包已生效的兼容合同，不把兼容值当所有项目的设计目标。

原文提及的 `templates/acceptance-parameters.json`、`config.ownerParameters`、探针参数映射及规则快照升级能力，在此版本尚未实现或接入；它们是待开发能力，不可宣称已经生效。当前纳入的是文档规范和 context 阅读入口，Agent需自行记录适用参数及未测试项。本规则更新不改变既有候选、站点、包、验收或设计师确认状态。

本条补充不把 Games 的行为规则推广到 App/Coupon。冲突时最新用户指令优先；例如本次三个站详情允许头部导航、手机详情顶部推荐隐藏，覆盖旧三站配置中的相反描述。
