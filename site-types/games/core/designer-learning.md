# Games 设计优化经验的持续使用

这是制作与检查方法参考，来源是中央团队库的真实 Games 创作反馈，不是新的统一皮肤，也不是既有页面已通过验收的证明。机器入口为同目录 `designer-learning.json`，保留来源 ID、版本、页面、检查方法和例外。当前快照归并了38条反馈的19个主题；来源被纠正或撤回时，应按原 ID 更新，不另造同义规则。

## 制作时怎样使用

1. 先读当前 owner 合同，再按真实能力、页面和组件选择经验。新建与授权维护的首页必须有游戏主网格、真实可清除的最近浏览、本站介绍；这一2026-10-30用户直接要求优先于早期“可选”的表述。
2. `qualityWorkflow: 2` 的 `plan` 按路由生成经验决定项，列出实际组件和样本候选；Agent逐项记录采用的实际组件、方法、实现、样本与候选证据，或给出不适用理由。参考的品牌皮肤不自动成为硬规则；必须有真实检查，不能仅记录“已读取”。
3. 制作前查真实数据、长名称和实际容器。先决定内容分组、主次与动作位置，再确定密度、间距、背景和动效。同一品牌同用途组件一致，不同品牌的内页和手机布局保留实际差异。
4. 预览后检查真实像素与行为。局部修改构建后先给预览，按实际受影响的组件/调用位置复验；经验整理与同步不阻塞交付。文档或自动几何检查不能代替视觉和真实交互观察。
5. 新任务联网查询相同 Games 页面键，包含候选及撤回状态。此文件是明确时间点的快照，不具备自动联网或自动发现新撤回的能力；离线使用时说明这一限制。

## 重点方法

- **主次和容量**：网格、大小卡、标题、按钮、推荐及末行一起判断；按真实宿主宽度重组，不用放大最后一张或无意义留白填满页面。
- **游戏信息**：普通名称单行省略并保留完整访问名称；星级对应真实平台与数值，未知评分留空；蒙版和操作不遮挡信息。
- **手机操作**：实际检查首次点击、焦点、按下和返回；桌面 hover 不能吞掉手机首点，图片尺寸合格不代表触控或游戏已可用。
- **加载与方向**：图片占位、站点启动层、游戏自身加载分清职责；有 ready/progress 协议时使用真实协议。iframe load 不是游戏可玩证明，不按计时器伪造进度；按实际 portrait/landscape/responsive 能力安排画框。
- **背景和动效**：装饰分布有节奏，服务内容；实际采样动画状态，检查引用的关键帧、加载切换边界、离屏暂停和 reduced-motion，不用声明存在冒充动效有效。
- **信息页和导航**：文案符合本站实际功能、身份和联系条件；短页页脚与长页自然文档流分别处理；页头同族调用位置一起检查。
- **版本完整性**：修改、预览、截图和下载绑定同一个实际候选，不把两个端口或不同版本的局部成果拼成“全部完成”。

## 后续反馈闭环

保存必要的原话、实际对象、候选/截图指纹、修正和真实复验；未知根因不猜，未获准确候选认可不写“设计师已批准”。可迁移修复经验按中央库既有的确认、证据和作用域规则提交；主观参考保留为参考；重复案例补充原 ID 的证据，冲突保留待处理，失效来源不得继续支撑结论。直接用户的规范修改维护在版本化 owner 合同中，不用主观经验静默覆盖。
