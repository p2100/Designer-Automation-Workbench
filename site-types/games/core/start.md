# Start from the product

First read owner-games-rules.md and owner-requirements.json. The current games contract owns factual capability routing, card/action quality and the four-region play shell. The latest user-approved reference owns the requested layout; do not apply an older Topziz/Mzgen skeleton to every new brand. Maintain each site's identity and truthful actions.

For explicit restoration/1:1 or restoration-then-refinement tasks, first read [restore-and-refine.md](restore-and-refine.md). Freeze the faithful baseline before deciding or implementing improvements. Source fidelity and useful refinement are separate outcomes.

1. State who visits, what they want to accomplish, what the site actually does and the primary successful action. Web-play: discover → judge input/device → play → return. Store-referral: discover → understand → official store.
2. Inventory the reference's page families, routes and interaction states. Enumerating URLs is different from actually checking every page. Record sampling and unknowns. Learn useful patterns; do not reproduce its ad holes, errors or invented facts.
3. Define each site's own route/module map, visual target and mobile grouping. Freeze data sources and representative short/long/missing/last-row samples. Scope by site → page → module; integrate navigation and whole-site rhythm afterwards.
4. Probe actual tools and save capability evidence. Missing browser/touch/image generation/independent review is not-run. A configuration file alone proves no connection.
5. Initialize a new run and read page/stage context. Build the first home/detail direction, independently review it, then expand. Fix issues centrally and freeze a new candidate after changes.
6. Validate every emitted route/link and content identity. Observe representative templates/modules/states on desktop, phone, 320px and breakpoint neighbors. Execute real actions. Compare same-purpose sites at the same widths, including ordinary modules and mobile.
7. Freeze, independently review, repair, then export. Unzip to a clean directory, verify bytes and repeat entry/routes/action smoke tests. Record implementation, source integrity, visual review, functional testing and user acceptance separately. Do not publish or commit unless requested.

The latest [owner standards](owner-standards-20261027.md) (from a core file: owner-standards-20261027.md) apply in every author/review phase. They supersede older homepage category, inner-width, fullscreen and surface-palette directions. Use the portable inspector and actual browser/Image capabilities; preserve feedback and distinguish not-run from a pass.
