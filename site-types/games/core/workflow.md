# Work phases

resolve → plan → make → check → review → deliver.

- resolve: clarify product, source and authorized scope; inspect the actual repository/reference. Record material unknowns. Do not ask users for facts available in files/tools.
- plan: per-site page/module contracts, real samples, visual target, capacities, breakpoints and state coverage. State what is reference observation, requirement, budget or justified exception.
- make: implement one site at a time, including its complete home/detail/play flow and applicable checks, before authoring the next. Reuse factual/behavior contracts, keep visual renderers and mobile grouping independent. Asset/data preparation may be shared; a batch renderer with palette substitutions is not site-specific design.
- check: exhaustive routes/links/media plus meaningful real interactions and responsive observations. Capture after actual scrolling/loading. Separate pending lazy images from broken media; prove the final state.
- review: independent role reads exact candidate and pixels, inventories actual modules, reports all issues once. No reviewer code edits. Author repairs; new candidate and affected regression.
- component repair: expand a reported defect to its entire affected family: sidebar, lower recommendations, home/detail/play variants, search results, hover/focus and first/middle/last rows. Declare exhaustive identity/link/media scope separately from representative visual scope; use the same visit for multiple applicable checks rather than repeating it for each rule.
- version check: before judging a reported regression, identify the exact build and same entity/route. Keep historical artifacts immutable. Move a review to the corresponding current version only when it will not discard active user input or game state; otherwise open a separate current preview.
- deliver: source, artifacts, source/adaptation manifests, version, screenshots, test coverage and unresolved limits. Extract final archive to a clean location; verify and open the extracted entry. No automatic deployment or Git commit.

The latest [owner standards](owner-standards-20261027.md) (from a core file: owner-standards-20261027.md) apply in every author/review phase. They supersede older homepage category, inner-width, fullscreen and surface-palette directions. Use the portable inspector and actual browser/Image capabilities; preserve feedback and distinguish not-run from a pass.
