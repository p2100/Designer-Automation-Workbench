## 已确认的边界

- 独立 App-Automation 规则包；Coupon、Games 暂时保持现状。
- 首版英文，覆盖 PC/手机；允许下载型手游，不接浏览器在线玩流程。
- 同时支持 Android 安装包获取和 Google Play/App Store 官方商店导流，按真实应用能力选择渠道。
- 统一业务结构、模块关系与质量底线，构图、品牌、侧栏、卡片语言及跨端布局保留自由。
- 默认不添加广告位，不继承参考站的广告空白。
- 使用现有文件/商店来源，兼容已有内部文件源，本轮不建立安装包托管服务。
- version 是下载承接页；历史版本只在有真实数据时作为可选模块。

## 页面合同

| 页面 | 最低结构 | 模块与动作关系 |
| --- | --- | --- |
| 首页 | 品牌导航、精选 App、分类入口、分组 App 列表、文章入口、信息页脚 | 应用卡进入对应 detail；分类进入该分类结果；文章进入正文。精选不强制轮播，分组不强制排行榜或固定栏目数量。 |
| 文章 | 标题、与选题匹配的正文、真实应用关联、相关内容/返回路径 | 支持评测、教程、专题/对比；正文中的应用卡进入对应 detail。按选题使用步骤、对比、截图等，不要求每篇塞满所有模块。 |
| 分类结果 | 分类身份、匹配的应用列表、分类切换/返回路径 | 列表只含该分类内容；数量/排序有真实依据才展示；分页/加载更多按实际数据量选择，有则真实工作。全部分类总览可选。 |
| detail | 真实身份、基本信息、截图、介绍/核心功能、获取入口、相关推荐 | 主按钮进入当前应用 version，允许补充准确标注的官方商店直达。身份和获取动作优先于无关推荐。 |

| 搜索（可选） | 查询入口、输入回显、结果、空结果与恢复路径 | 实现则能搜到正确应用、清空并恢复；未实现不放假搜索框。 |
| 信息页 | About、Contact、Privacy、Disclaimer、404 | 信息与实际站点身份和行为一致，联系入口真实；404 提供可用恢复路径。Terms 按业务需要增加。 |

## 数据与身份

每个应用使用稳定身份，文章、卡片、截图、detail、version 和渠道目标保持同一实体。Google Play 包名与 App Store 商品 ID 分平台绑定，不能因名称近似就拼在一起。

名称、真实图标、适用平台和正文必须能说明当前是什么应用；截图使用对应应用的真实产品截图，宣传插画不代替。生成时应记录来源及取得时间，平台/地区差异不能混填。

评分、下载量、版本号、文件大小、更新日期、兼容要求、评论、历史版本等按可靠数据展示。未知不补造，Latest 不能冒充具体版本号，没有评分就不画假的五星。关键身份或渠道缺失时如实标明不可获取，不能用占位按钮冒充完成。

## 布局与制作方法

- 先明确页面任务与各模块的阅读顺序，再设计列数与卡片；六站的具体栏目名、顺序、数量和侧栏形式是参考方法，不是强制模板。
- PC 可用居中主内容或主栏/侧栏；手机主动重组，保持当前应用身份、截图、介绍和获取动作清晰，不按桌面整体缩小。
- 普通应用卡保持同用途规格和完整身份可辨认；摘要可按明确容量缩略，详情主标题和主要获取信息不靠截断省略解决空间问题。
- 图标保持身份完整，产品截图保持原始比例；画廊局部横滑不等于允许整页横向滚动。长名称、末行、缺图/加载/失败、不同屏幕均需检查。
- 明确卡内边距、元素间距、标题到模块和模块之间的层级，检查完整页面，排除无用途空洞与推荐抢占主体。
- 正文约16px、辅助信息约14px可作为初始制作预算；图标/字号/列数根据用途和实际内容调整，不套 Coupon/Games 的专属数值。主要触控目标以44px为制作目标，最终仍需检查文字和实际热区。
- 页面的主要结构在可编辑初始 HTML/CSS 中形成，脚本负责真实交互；不使用浏览器运行后重新拼接布局或遮盖来掩饰首屏问题。

## 获取流程与状态

主路径：发现/分类/文章 → detail → version → 真实渠道。补充商店直达必须明确平台；无法匹配当前应用的链接不展示成可用入口。

外部安装包和官方商店是不同渠道。不得制造空锚点、指向自身的假下载或 undefined 链接，不自动声称下载完成、已安装或已安全扫描。可达性、下载事件、完整文件和安装成功是不同事实，证据只支持实际执行过的层级。

页面必须保留可恢复路径。截图画廊、导航、筛选、分页等有控件就真实工作，缺失/失败不能留下无限加载。普通 hover/focus/pressed 状态不推挤相邻内容。

## 生成与审核的记录

正式规则区分：用户硬要求、适用业务要求、制作目标、参考观察、可选模块、例外和未覆盖范围。每项有稳定 ID、适用页面及核对证据，制作与审核使用同一来源。

审核须覆盖整页、关键模块、长短内容、实际导航/渠道以及 PC/393/320 和布局切换附近；不能以文件完整、HTTP 200 或计划填写代替视觉和功能通过。没有执行的检查记 not-run，不用参考站有此文案来证明新站通过。

本轮建立规则包和匹配清单；站点生成、业务站点联测、安装包托管以及多类型共享经验服务接入不属于此次规则整理。
