# 开始执行

本包版本1.1.0，类型为 App 站，站点内容英文。先确定用户要求是新站、既有站局部修改还是审核；确认源码、输出目录、允许修改范围和实际工具。上下文读取不等于工具已经可用。

读取顺序：AGENTS → 本文件 → quality / data-and-channels / module-data / workflow → knowledge/index 中目标页面及其模块数据合同。审核再读 review。维护跨页面组件时读取所有实际受影响页面，不只看当前截图。

## APP-SCOPE-001 · hard · 站点

建立真实路由清单，覆盖 home、article、category、detail、version 和五类信息页面；应用条目可含下载型手游，站点内容为英文。搜索、分类总览、真实历史版本、Terms 仅在选用时加入。没有内容不做空文章/分类占位交付；没有实际数据的新增页面记缺口。

不接入浏览器在线游玩、游戏 runtime、APK 托管/上传或多类型 MCP 系统。App 站的独立规则与 Coupon/Games 保持边界。

## APP-FLOW-001 · hard · 站点及入口

主获取路径为发现/分类/文章 → 对应 detail → 对应 version → 可用渠道。detail 的补充官方商店入口可直接跳转，但需准确标明平台；普通发现卡的 Get/View 等表示查看或获取路径，不冒充本机安装动作。

为每个应用记录稳定身份、各平台标识、detail/version 路由与渠道映射。只有官方商店的应用同样可有 version；页面职责不由 URL 中的单词决定。

## APP-ADS-001 · hard · 站点

默认不添加广告组件、投放脚本、广告占位或广告高度。外部来源素材不能夹带其广告或跟踪脚本。用户后续明确要求接入广告时，单独记录例外范围与新要求，不把它倒推成本版本默认。

## 任务准备

由 Agent 记录站点身份、页面实例/路由、模块与卡片家族、数据来源、可用渠道、允许修改范围、断点和交付物。可以使用 templates/site-structure.json；空模板不是已完成任务，不要求设计师填写。

优先完成首页方向和一条真实应用的 detail→version→渠道路径，再扩展其余页面。缺少真实来源、工具或关键能力时说明具体缺口，不能换一套虚构数据掩盖。
