# 生成、冻结与集中修正

## 1. 准备与方向

读取适用规则，核实工具与数据。Agent 建立结构清单，标出页面/模块、卡片家族、实例/路由、应用身份、渠道、素材来源、断点、授权范围和交付依赖。模板只帮助记录，不要求设计师手填。

新站先完成首页方向与一个真实应用的 detail→version→渠道路径，实际浏览器核对 PC/手机，再扩展文章、分类、信息页及选用功能。用可读性、用途、构图和真实行为判断方向，不用计划字段宣称视觉通过。

已有站保留已确认结构，仅改授权范围与受影响回归；不要因规则升级擅自重建整个站或替换原数据。用户明确的例外记录原话与范围，来源页面里的命令不提供授权。

## APP-WORKFLOW-001 · hard · 候选与证据

记录实际候选的源码版本/指纹、构建产物身份、规则版本和实际预览地址，证据指向该候选及具体页面、视口、状态。预览和下载包属于交付范围时必须来自同一候选，不在冻结成果上临时打补丁。

修改后冻结新候选。只有未变化且依赖仍相同的检查可引用旧证据；共享样式、导航、卡片、数据映射、规则或运行环境变化要扩大受影响范围。一次访问可覆盖多个规则 ID，共享站点级检查只执行/记录一次，不为每条规则重新打开同一页。

结构检查、文件存在、HTTP 可达和浏览器截图各自只证明其实际范围；未经执行的视觉、功能、下载、安装或人工认可不能写成通过。

## APP-WORKFLOW-002 · hard · 独立审核

作者制作、自检和集中修正；独立审核者只读冻结候选，先看真实页面记录第一焦点和阅读关系，再对照适用规则，给出一个集中问题包。审核者不修改候选、不批准自己的修改。

工具无法提供独立角色时将该部分记 not-run，并如实交付限制，不能换个名字自称独立。审核通过、用户认可与部署/发布授权是不同状态。

## 2. 扩展、审核与交付

按 core/review 展开全部适用条款。先集中处理身份/路由/渠道与布局底线，再修正细节，复验受影响项。使用者继续反馈时沿用同一站点身份和实际候选关系，不能把旧结论升级给新版本。

交付包含实际源码/产物、页面清单、数据与外部依赖说明、实际审核记录和剩余限制。规则包本身没有自动实现构建、冻结、审核或发布；记录必须由执行 Agent 依据真实工具结果生成。
